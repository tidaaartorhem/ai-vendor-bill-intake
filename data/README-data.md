## 2. Seeded intake feed (ALL FICTIONAL — disclosed)

Generated by `scripts/seed_bills.py` with `random.Random(20261102)`.
Re-running reproduces byte-identical JSON (fixed seed, sorted keys).
SME: **Portside Supply Co.**, Toronto wholesaler. Intake desk
`ap@portside.example`. All vendor emails use `.example` (fictional).

### Real-data sampling (disclosed)
Line items are built from real corpus tuples: 6,000 distinct
`(Description, Quantity, UnitPrice)` tuples sampled (seeded) from rows with
`Quantity > 0`, `UnitPrice > 0`, non-null Description. Bill line counts follow
the measured distribution (P50 ≈ 11, P90 ≈ 48 lines/invoice). Quantities are
scaled so bill totals land in the intended bands; unit prices are real corpus
prices. Bill total bands were anchored on the measured invoice-total
P50 ($303.84) / P90 ($940.89): ~55% of bills $200–$1,000 (AUTO-INTAKE tier),
~30% $1,000–$4,000 (MANAGER tier), ~15% $5,000–$12,000 (DIRECTOR tier).

### Vendor register — `data/outputs/vendor-register.json`
40 vendors (`V001`–`V040`), schema
`{"vendor_id","canonical_name","po_required","currency"}`.
36 CAD, 2 USD, 1 EUR, 1 GBP (FX path). 10 vendors have `po_required: true`
(V001, V006, V011, V013, V024, V030, V031, V032, V034, V036).

### Bills — `data/outputs/bills.json`
120 arrivals `B001`–`B120`, `received_at` 2026-10-26 → 2026-11-02T08:41:00-04:00
(replay Mon 2026-11-02 08:41 EST). Per bill:
`{"bill_id","received_at","from","subject","body","bill_text","seed_flags"}`.
`bill_text` is the document the extract regexes parse: vendor name line,
`Invoice # NNNN` / `INV-NNNN` / `No. NNNN` variants, `Date:` in three formats
(`Oct 28 2026` / `2026-10-28` / `28/10/2026`), optional `PO: PO-NNNN`,
`Currency: XXX`, line rows `"<qty> x <desc> @ $p"`, `Subtotal:`,
`Tax (HST 13%):` on CAD bills / `Tax (VAT 0%):` on foreign bills, `Total:`.
CAD totals include 13% HST; foreign bills are zero-rated at the border
(total = subtotal). Money is integer cents throughout; exact half-cent
tax/FX roundings are detected and regenerated so every printed figure is
unambiguous.

### Seeded noise (every bill tagged in `seed_flags`; counts verified)
- `name_variant` ×6 — display-name variants of register vendors
  (token-set Jaccard vs canonical: 0.75, 0.60, 0.75, 0.80, 0.667, 0.75 —
  all ≥ 0.60, so all resolve): B001–B006.
- `exact_resubmission` ×4 — same vendor + invoice number as a posted-register
  entry (D1): B007–B010.
- `near_duplicate` ×4 — same vendor, total +0.4% (within 1%), invoice date
  +3 days (within 7), invoice number differs; one has NO invoice-number line
  (B014): B011–B014.
- `split_cluster` ×4 — vendor V031, same PO `PO-5520`, totals exactly
  $4,600.00 / $4,750.00 / $4,825.00 / $4,900.00, invoice dates Oct 27, 28, 30
  and Nov 1 (5-day window), cluster sum $19,075.00 > $5,000 tier → SPLIT_DODGE:
  B015–B018.
- `missing_po` ×3 — no PO line from `po_required` vendors (V001, V013, V024):
  B019–B021.
- `unfooted_total` ×2 — printed header total ≠ Σ lines; doctored by
  +$8.38 (+0.70%) and +$11.68 (+0.70%), both > $0.05 AND > 0.5%: B022–B023.
- `future_dated` ×1 — invoice date 2026-11-09, after replay 2026-11-02: B024.
- `round_number` ×2 — printed totals exactly $2,000.00 and $3,000.00: B025–B026.
- `clean` ×94 — no noise, includes one bill from each foreign vendor (FX path).

## 3. Test vectors — `data/test-vectors.json`
14 vectors, `{"id","rule","description","input","expected"}`. Hand-computed;
expected totals to 2 decimals, dates ISO `YYYY-MM-DD`. This file is the
contract: the Python pytest and the TS vitest both read it and must agree
exactly. Covers: extract (invoice# variants `Invoice #` / `INV-` / `No.`,
3 date formats, line items, subtotal/tax/total, `US$` currency symbol, PO ref),
alias resolution (0.60 boundary resolves; 0.20 stays unresolved), D1 exact,
D2 near-duplicate, V1 future-dated, V2 unfooted, V3 missing PO, V4
round-number, split-dodge cluster, routing tiers + USD→CAD FX.

## 4. Golden set — `data/golden-set.json`
30 bills referenced by `bill_id` with ground-truth labels
`{"bill_id","vendor_id","invoice_number","invoice_date","total_cad","expected_action"}`:
6 clean AUTO_POST, 3 clean SEND_TO_MANAGER, 1 clean SEND_TO_DIRECTOR,
4 HOLD_DUPLICATE (exact), 4 HOLD_DUPLICATE (near), 4 SEND_TO_DIRECTOR
(split cluster), 3 REQUEST_PO, 2 CORRECT_TOTAL, 1 future-dated
SEND_TO_MANAGER, 2 round-number SEND_TO_MANAGER (V4 is a low-weight flag;
routing follows the $1k–$5k tier). For unfooted bills `total_cad` is the TRUE
line-sum total, not the doctored header. `invoice_number` is `null` for B014
(no invoice-number line).

## 5. Label rules (for the pipeline implementer)
- normalize: vendor alias via token-set Jaccard ≥ 0.60, tie-break longest
  canonical name; dates → ISO; foreign totals → CAD via fx-table.
- dedupe: D1 exact (vendor_id + invoice_number in posted register) →
  DUPLICATE; D2 near (same vendor + total within 1% + date within 7 days +
  invoice# differs/missing) → LIKELY_DUPLICATE.
- validate: V1 future-dated (invoice_date > 2026-11-02); V2 unfooted
  (Σ lines vs header total differs > $0.05 AND > 0.5%); V3 missing PO for
  po_required vendors; V4 round-number total ≥ $1,000 → REVIEW flag, low weight.
- split_detect: same vendor + same PO, invoices within a 7-day window; any
  invoice in the $4k–$5k band and cluster sum > $5,000 → SPLIT_DODGE.
- route: < $1,000 AUTO-INTAKE; $1,000–$5,000 MANAGER; > $5,000 DIRECTOR;
  any duplicate or validation flag → REVIEW.
- actions: AUTO_POST / SEND_TO_MANAGER / SEND_TO_DIRECTOR / HOLD_DUPLICATE /
  REQUEST_PO / CORRECT_TOTAL.
